# サイト共通UI標準

制定日：2026年11月25日。対象は和奏人事パートナーズの通常公開ページと、新しく生成・追加する通常ページです。本ルールは既存本文やLPの申込導線を変更するためのものではありません。

## 1. 適用範囲と例外

全通常ページに、トップページと同じ主要ナビゲーション、TOPへ戻る正式ロゴリンク、共通スマートフォンメニュー、ページ上部へ戻るボタンを配置します。コラム一覧・カテゴリ・記事、セミナーLP、問い合わせ完了ページ、規約・サイトマップ等の簡潔なページも対象です。本文の見出しを持つ `header` と、サイト全体のヘッダーは区別します。

転送専用ページ（`/ad-a/`、`/ad-b/`、`/seminar6/`、`/governancesaiyouseminar/`、`/home/`）と404ページは共通UIの追加対象から除外します。転送用HTMLのmeta refresh・移動先・本文は変更しません。`/coming-soon/` は404を維持し、新しい通常ページやリダイレクトを作成しません。

## 2. ナビゲーションの内容・URL・順序

PCの主要ナビは、トップページの次の8項目と完全に一致させます。スマートフォンメニューは先頭に「TOPページ」への `/` リンクを追加した、TOP＋同じ8項目です。

| 順番 | 表記 | URL |
| --- | --- | --- |
| 1 | なぜファミリー企業 | `/family/` |
| 2 | 私たちの想い | `/philosophy/` |
| 3 | サービス | `/service/` |
| 4 | ファミリーガバナンス | `/family-governance/` |
| 5 | セミナー | `/seminar11/` |
| 6 | コラム | `/column/` |
| 7 | 会社概要 | `/company/` |
| 8 | ご相談・お問い合わせ | `/contact/` |

各通常ページのPCサイトナビは1個、`.site-menu-trigger` は1個、`.site-mobile-nav` は1個とします。ページ固有の目次・パンくず・フッターの関連リンクは別用途であり、共通サイトナビと混同しません。フッターメニューの表記と行先は既存を維持します。

旧サイトヘッダーや旧 `.mobile-nav`／`.menu-button` を非表示のまま重複して残さないでください。撤去前にローカルJSの参照を確認し、専用のインラインメニュー処理は重複要素と一緒に整理します。本文のFAQ・フォーム等の動作を持つJSは維持します。

`aria-current="page"` はリンク先と現在のページURLが同じときだけ使います。記事・カテゴリの `/column/` は所属セクションを示す `aria-current="location"` とし、コラム一覧ページ自身は `page` とします。問い合わせ完了ページから `/contact/` を現在地扱いするときも `location` とし、問い合わせページそのものとは区別します。

## 3. 正式ロゴリンク

サイトヘッダーには正式ロゴ `assets/images/logo.png` を1個配置し、`href="/"` の `a` リンクにします。各ヘッダー・フッターに既にある正式ロゴも全てTOPへのリンクにします。相対画像パスはそのページから正しく同じ正式画像に解決されれば維持できます。

既存リンクは保持し、未リンクの正式画像だけを短い `a` で包みます。リンクの入れ子を作らず、画像のalt・寸法・既存クラスを不要に変更しません。人物写真、アイキャッチ、事例画像等をロゴと見なして包むことは禁止します。

## 4. 共通スマートフォンメニューとページトップ

`body` に `site-menu-enabled` を付与し、`.site-menu-trigger` の `aria-controls` と `.site-mobile-nav` のIDを一致させます。メニューは初期状態を `hidden`、トリガーを `aria-expanded="false"` とし、閉じるボタンを1個備えます。キーボード操作、フォーカス復帰、Escape、背景スクロール抑止を共通JSで扱います。

全通常ページに `type="button"` と日本語の `aria-label` を備えた `.site-page-top` ボタンを1個配置します。表示タイミング、フォーカス、クリック／キーボードでの復帰、スクロール動作は共通CSS／JSで管理します。セミナーの固定申込ボタン等と重ならないことを確認します。

次の4資産は、各通常ページでそれぞれ1回だけ読み込みます。

- `assets/css/site-menu.css`
- `assets/js/site-menu.js`
- `assets/css/page-top.css`
- `assets/js/page-top.js`

2026年11月25日の共通UI改修では全てのqueryを `?v=20261125-common-ui1` とします。既に読み込む `assets/css/site-footer-nav.css` も同じqueryに統一します。ページ固有のCSS／JS、コラム本文用CSS、日本語改行用 `japanese-line-wrap.css/js` のバージョンは本変更で更新しません。今後共通UI資産のキャッシュ更新が必要なときは、HTMLと生成テンプレートを同時に更新します。

## 5. セミナーLPと生成テンプレート

`/seminar11/` も通常ページなので、専用LPであっても今回の共通8項目ナビが必要です。`.flyer-header` と `.flyer-brand` は維持し、正式ロゴをTOPリンクにし、ヘッダーに `.site-desktop-nav` を追加します。既存の「オンライン・無料セミナー」という専用案内、本文、申込CTA、スマートフォン固定申込導線は保持し、専用の案内と共通サイトナビを両立します。

採用実績カードの重複期間表記3か所を削除した別途承認済みの状態は維持します。上段 `dt` の期間・時点、および「3名全員」「4名」「7名」の数値・文言を変えてはいけません。

新しいコラムを生成するときも同じロゴリンク・ヘッダー・スマートフォンメニュー・ページトップ・共通資産バージョンが再現されるよう、`scripts/build-columns.mjs` のテンプレートを更新します。構造化データには本文用の `span` や日本語改行マークアップを混入させず、JSON-LDを有効なJSONのまま保持します。

## 6. 改修・検証・公開手順

HTML全体をBeautifulSoup等で再serializeしてはいけません。UIに必要な限定文字列・要素範囲だけを変更し、無関係な文言、数値、meta、JSON-LD、フォーム、本文、インラインstyles、CTA、フッターリンクを保持します。

機械検証は次のコマンドで実行します。Python標準ライブラリのみを使用し、HTMLを書き換えません。

```sh
python3 scripts/verify-site-common-ui.py
python3 scripts/verify-site-common-ui.py --json
# 任意の作業ツリーを検証
python3 scripts/verify-site-common-ui.py --root /absolute/path/to/preview
```

現行通常20ページのPC8項目とSP TOP＋8項目、正式ロゴリンク、重複UI撤去、メニュー・ページトップの個数、資産個数とquery、現在地、JSON-LD、転送5HTMLの基準ハッシュ、`coming-soon` の不在を確認します。将来通常ページが増えたら検証対象リストも追加します。転送先を変更する正式な別件承認がある場合に限り、基準ハッシュを承認内容と同時に見直します。ファイルの不在確認だけではHTTP 404の証明にならないため、preview公開先でもHTTPステータスを確認します。

表示・操作検証はPC幅 **1440／1280／1024／768px** とSP幅 **390／375／360／320px** で行います。ナビ・ロゴ・CTAの重なり、横スクロール、メニュー開閉・スクロール・閉じる・Escape・フォーカス、ページトップの初期非表示とスクロール後表示・復帰、セミナー固定申込導線との非重複、本文とフォームの維持を確認します。ブラウザーを使用できない作業では未実施であることを明記し、許可された担当へ引き継ぎます。

共通UI改修は **preview限定** で行い、**明示承認された差分だけをpublish** します。確認・承認前に本番へ適用したり、preview確認を理由に既存本文やLPを全面的に置き換えたりしません。固定配信previewrepoへの同期も担当者が承認済み差分として行い、別作業者が無断で編集しない運用とします。

## 7. 固定操作ボタンを画面外へ押し出す長い語句

2026年11月25日の実表示検証で、3記事のH1とサイトマップにある長い `jp-keep` が、本番基準でもスマートフォンの横はみ出しを発生させ、固定メニューボタン・ページトップボタンの表示領域に影響することを確認しました。本文の書き換えや文字縮小は行わず、「ここで働く／自分を／想像できる」「これからの／会社を一緒に／つくる人」「最初に／見直すべきこと」の短いまとまりに分けています。スラッシュは説明上の区切りで、原稿やHTMLの文字列には追加しません。

同じ指定を `content/columns/` の3記事の `title_keep_phrases` に保存し、再生成で長い一括nowrapへ戻らないようにします。新規記事の語句保持指定も、320pxの実幅・実フォントで検証してください。横はみ出しをoverflowで隠す、フォント縮小・横圧縮・省略することで解決してはいけません。この調整は、固定操作ボタンの到達性を確保するために必要な最小限の文字組み差分として、共通UIのレビューに明示します。
